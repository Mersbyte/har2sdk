# Security & privacy

## Reporting a problem

If you find a way for recorded data (cookies, tokens, personal data) to end up in generated files, prompts, MCP responses or mock responses, or a way for a crafted HAR file to inject code into a generated client, please report it privately through GitHub's **Report a vulnerability** button on the repository's Security tab instead of opening a public issue. Please do not attach real HAR files: describe the shape of the input or build a minimal synthetic one. `har2sdk inspect capture.har --json` replaces the values the leak guard knows about, but review it before sharing — see *Limits*.

## What har2sdk does to protect recorded data

- The CLI and library make no network requests.
- **Leak guard.** Before generating anything, har2sdk collects
  - recorded values that look like data: ids with three or more digits or an id shape (`ord-77314`, `PROJ-7`), letter-only tokens that look random (judged by rare letter pairs and case flips: `KfTqLmZxRwPbNvYc`, `xkq-bvzt-rmn`), emails, phone numbers, long numbers, free text, URLs with query strings, relative paths with ids, secrets;
  - anything under a personal, secret or id key (`name`, `email`, `birthDate`, `token`, `id`, `orderNumber`…, with common Turkish, German, Spanish and French key words), CSV cells and XML elements under personal names, literals inside GraphQL documents (POST, GET and batched), and data inside query and form parameter *names* (`role[someone@…]`);
  - **identities**: values under `login`, `username`, `owner`, `author`, `sender`, `reviewer`, `approver`, `id`… and in `x-user` / `x-tenant` / `x-org` headers, whatever they look like (`okilic`, `oguzs-clinic`, `ACME`), in any spelling (`ece_kaya` / `ece-kaya` / `ece.kaya`);
  - **labels**: one-word names of things (`"Books"`, `"Premium"`) found only under a `name`-like key of an object that doesn't describe a person. They are treated as data by the generator but not reported by the scanner (see below).

  The generator consults that set while deciding what may become code: a recorded id-shaped value or identity can't stay a path literal; dictionaries keyed by data or identities (or two or more same-shaped entries keyed by recorded values) become `Record<string, T>`; enum members must be vocabulary that is not recorded as data, a label, an identity or a word of a recorded personal name (`"zeynep"` when `"Zeynep Ak"` is a `fullName`; the mock fakes such words too), and only technical fields (`status`, `type`, `currency`…) get enums at all; query parameters whose names carry data are left out with a warning; cookie names and version metadata carrying recorded data are not listed; GraphQL string, list and block-string literals, and numbers under id arguments or with six digits or more, become variables. The HAR file's name is not written into generated files.

  Afterwards every output is scanned:
  - `client.ts` and `openapi.json`: if a recorded value is found — as a token, as an identity inside a longer token (`remember_okilic`), percent-encoded, or as an identifier form (`OguzKilic`) — the CLI writes **nothing** and exits with status 2, showing masked previews (`og…ev (email, 14 chars)`); `--allow-leaks` overrides. The MCP `generate_sdk` tool refuses the same way unless `allow_leaks` is set. Not reported: labels, labels of the API's own host names, and words har2sdk writes into every client (`ApiError`, `har2sdk`). With `--examples`, the examples in `openapi.json` are scanned too; only recorded dates and timestamps are not reported there, because the fake data keeps them on purpose;
  - the chat prompt, MCP responses and `inspect --json`: everything the scan above would report is replaced with `<redacted>` (identifier forms with `Redacted`) — values, identities inside longer tokens, slugs and host names spelling a recorded name (`zeynep-ak.s3.amazonaws.com`), names a singular form shortened (`OguzDemirtaSetting`), and percent-encoded forms. A test checks that scanning the redacted text finds nothing.
- What generated files *do* take from the capture: the base URL and any secondary origins, path segments judged to be resource names, property names, version/platform header values (`3.4.1`, `ios`), non-session cookie and header names, vocabulary-like enum values of technical fields (`"shipped"`), and GraphQL documents with their data-carrying literals turned into variables.
- `--examples` and the mock server serve **fake data with the recorded shape**, for JSON, XML, HTML, CSV and plain-text bodies: property names never change; ids, usernames and slugs are replaced with consistent same-shape fakes (salted per run, so they can't be reversed by hashing guesses; a fake never equals the recorded value), also in URL paths, in file names (`avatars/<user>.png`, `<user>_avatar.jpg`) and in host names named after a user; small numbers, timestamps and vocabulary under technical keys stay; large integers are faked; IPs become documentation addresses; names, free text, emails, phone numbers, personal dates (and calendar dates in a person's record), locations and URL query strings are masked; other words are faked. `har2sdk mock --raw` serves the recorded bodies unscrubbed (JSON re-serialised, values unchanged).
- `har2sdk mock` listens on `127.0.0.1`, answers only `localhost`, `127.0.0.1` and `[::1]` Host headers (a page using DNS rebinding gets 403), and allows CORS only from `localhost` and the recorded origins.
- The MCP server only reads `.har` / `.json` files; writes only inside the HAR's folder, its working directory (not when that is `/` or the home folder) or the temp directory, checked on the real path (`realpath`); and refuses to overwrite a `client.ts` / `openapi.json` it did not generate.
- Neither the MCP server nor the CLI writes through a symbolic link: a linked output folder, a linked folder between the allowed folder and the output folder (MCP), or a linked `client.ts`, `openapi.json` or `har2sdk.annotations.json` is an error. Files are written under a fresh temporary name and renamed into place, so a link created in between is replaced, not followed.
- Text from a HAR is always escaped in generated code; a hostile HAR must not be able to run code when the generated client is imported.
- Control characters (escape sequences such as OSC 52 "write to clipboard") are removed from everything the CLI prints, from the prompt it copies and from MCP responses; the CLI's own colours stay.

## Limits

The leak guard is a heuristic. It cannot recognise a value that has no evidence anywhere in the capture — a plain word that appears once, as a path segment, never echoed by a response, never listed by a collection and never stored under a personal or identity key. Such a value can become a path literal and a method name, and appears in `inspect` output. A one-word name of a thing (a repository, a project, a category) counts as vocabulary unless the capture lists it as a member of the collection its path segment follows. The mock serves such unrecognised values in text bodies as recorded only if they look like vocabulary. Random-looking tokens without digits are recognised by letter statistics: long mixed-case tokens almost always, short or lower-case ones (`xkqbvtrm`) only about half the time, and a camel-case name made mostly of acronyms can be taken for one (it then becomes a path parameter). Review `har2sdk inspect` before publishing generated code. Treat `.har` files like passwords.

These behaviours are covered by the test-suite: `test/review*.test.ts`, `test/edge.test.ts`, and `test/privacy-fuzz.test.ts`, which generates a random person and a capture from a random subset of placement types with key names drawn from pools in five languages, and checks every output including a real MCP session and every mock response (30 seeds by default; the long run, `HAR2SDK_FUZZ_SEEDS=1000`, passes). The placement types and key-name pools are lists written by the authors; the test is evidence, not a proof.

## Acceptable use

har2sdk is meant for APIs you own or are allowed to use. Automating someone else's private API can violate their terms of service. Don't use it to access data you're not authorised to see, and don't publish generated SDKs for other companies' services.
